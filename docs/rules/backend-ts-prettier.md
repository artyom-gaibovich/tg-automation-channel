## Принцип

Форматирование полностью делегировано Prettier 3 — это устраняет стилевые споры и держит диффы чистыми. Конфигурация зафиксирована в `.prettierrc` и является единственным источником истины; ESLint не спорит с ней, а транслирует её нарушения как ошибки через `plugin:prettier/recommended`. Правила ниже — это прямое перечисление заданных опций и их следствий.

## Подробное описание

**[FMT-001]** Все опции собраны в `.prettierrc` (JSON). Форматирование не выполняется вручную и не настраивается пофайлово.

**[FMT-002]** `printWidth: 100` — строки переносятся при превышении 100 символов. Это подтверждается кодом: длинные сигнатуры контроллеров и конструкторов разбиты на несколько строк.

**[FMT-003]** `tabWidth: 2`, `useTabs: false` — отступ в два пробела, табуляция не используется.

**[FMT-004]** `singleQuote: true` — строковые литералы в одинарных кавычках (`import { Module } from '@nestjs/common'`).

**[FMT-005]** `semi: true` — выражения завершаются точкой с запятой.

**[FMT-006]** `trailingComma: 'all'` — висячая запятая в многострочных списках параметров, массивах и объектах (в т.ч. в последнем параметре конструктора сущности).

**[FMT-007]** `quoteProps: 'as-needed'` — ключи объектов берутся в кавычки только когда это синтаксически необходимо.

**[FMT-008]** `arrowParens: 'always'` — одиночный аргумент стрелочной функции оборачивается скобками (`(item) => item.text`).

**[FMT-009]** `bracketSpacing: true` — `{ foo }` с пробелами; `bracketSameLine: false` — закрывающая `>` многострочного JSX/тега переносится на новую строку.

**[FMT-010]** `endOfLine: 'lf'` — окончания строк Unix-стиля (LF).

**[FMT-011]** ESLint подключает `plugin:prettier/recommended`, поэтому расхождение с `.prettierrc` подсвечивается как ошибка правила `prettier/prettier`, а конфликтующие стилевые правила ESLint отключены через `eslint-config-prettier`.

**[FMT-012]** Форматирование с записью запускается `npm run format` (`prettier --write "src/**/*.ts" "test/**/*.ts"`). `npm run lint` дополнительно чинит формат через ESLint-интеграцию.

> **Версия:** Prettier `^3.0.0`. `trailingComma: 'all'` задан явно (в Prettier 3 это уже дефолт), `arrowParens: 'always'` также совпадает с дефолтом — но обе опции зафиксированы в конфиге явно, чтобы не зависеть от версии.

> **В проекте не обнаружено:** файлов `.prettierignore`, `.editorconfig` и настроек редактора (`.vscode/settings.json`) нет. Область форматирования ограничивается шаблонами скрипта `format` (`src/**/*.ts`, `test/**/*.ts`); отдельного скрипта `format:check` для CI также нет.

## Полная конфигурация

```json
// .prettierrc
{
  "printWidth": 100,
  "tabWidth": 2,
  "useTabs": false,
  "semi": true,
  "singleQuote": true,
  "quoteProps": "as-needed",
  "trailingComma": "all",
  "bracketSpacing": true,
  "arrowParens": "always",
  "endOfLine": "lf",
  "bracketSameLine": false
}
```

## Исключения и граничные случаи

| Ситуация | Как поступить |
|----------|---------------|
| Файл нужно исключить из форматирования | Завести `.prettierignore` (сейчас отсутствует); `dist`/`node_modules` и так вне шаблонов скрипта `format` |
| Проверка формата в CI без записи | Добавить скрипт `format:check` (`prettier --check ...`) — в проекте пока не заведён |
| Конфликт правила ESLint с Prettier | Разрешается в пользу Prettier через `eslint-config-prettier` (уже подключён) |
| Не-TS файлы (JSON, MD) | Текущий скрипт `format` их не охватывает; форматируются вручную по тем же опциям |
