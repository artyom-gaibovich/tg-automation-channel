# Команда: Извлечение правил работы с миграциями БД

Изучает фактический подход к миграциям базы данных и формирует документ правил `docs/rules/migrations.md`. Процедурная инструкция для исполнителя (LLM-агент или разработчик), без привязки к конкретному агенту.

## Назначение

Зафиксировать, как в проекте устроены миграции схемы БД и как с ними работать: инструмент миграций, расположение и формат файлов, конвенция именования, парность `up`/`down`, команды создания и применения, источник строки подключения. Документ выводит нормы из реальных файлов миграций и команд проекта, а не из ожиданий.

---

## Входные параметры

- Без обязательных аргументов — анализируется весь репозиторий.
- Необязательный аргумент `scope` — путь к подкаталогу (например, конкретный микросервис) для ограничения анализа.

## Источники в коде

| Что смотреть | Зачем |
|--------------|-------|
| `migrations/` | Расположение, формат и конвенция именования файлов миграций |
| Пары `*_<name>.up.sql` / `*_<name>.down.sql` | Парность прямой и откатной миграций, временна́я метка в имени |
| Содержимое `.up.sql` и `.down.sql` | DDL-стиль: таблицы, ограничения, индексы, обратимость отката |
| `Makefile`, `scripts/`, `docker-compose` | Цели/скрипты создания и применения миграций, профиль миграций |
| `CLAUDE.md`, `README.md` | Документированные команды `migrate create` / `migrate up` / `migrate down` и строка подключения |
| `configs/config.go` (секция `db.postgres`) | Параметры подключения, из которых собирается DSN для миграций |
| Импорты/зависимости (`golang-migrate`) | Инструмент миграций и драйвер источника (`file://`) |

## Алгоритм

1. Определить корень анализа (весь репозиторий или `scope`).
2. Найти каталог миграций и определить инструмент (golang-migrate) и драйвер источника.
3. Разобрать конвенцию именования файлов: временна́я метка, разделитель, имя миграции, суффиксы `.up.sql`/`.down.sql`.
4. Проверить парность: у каждой `up`-миграции есть соответствующая `down`-миграция.
5. Разобрать содержимое миграций: какой DDL применяется, как описываются ограничения и индексы, обеспечивает ли `down` обратимость `up`.
6. Извлечь команды создания и применения миграций из Makefile/скриптов/документации; зафиксировать формат строки подключения и её источник из конфигурации БД.
7. Определить, где и как миграции применяются (вручную, через профиль docker-compose, в CI/CD) — отметить фактическое, отсутствующее пометить как «в проекте не обнаружено».
8. Сформулировать правила с префиксом `MIGR`; непоследовательные практики (например, отсутствие обёртки в транзакцию, разнобой в регистре SQL) отметить явно.
9. Записать `docs/rules/migrations.md` по формату из [template-rules.md](./template-rules.md) и проверить по чек-листу.

---

## Что выявлять

- Инструмент миграций (golang-migrate) и драйвер источника (`file://migrations`)
- Расположение файлов (`migrations/`) и формат `.sql`
- Конвенция именования: `<timestamp>_<name>.up.sql` / `<timestamp>_<name>.down.sql`
- Обязательная парность прямой и откатной миграций
- Команды создания (`migrate create -ext sql -dir ./migrations <name>`) и применения (`up`/`down`)
- Формат строки подключения PostgreSQL и её источник из секции `db.postgres`
- DDL-конвенции: ограничения, индексы, значения по умолчанию
- Обратимость: `down` отменяет ровно то, что создаёт `up`
- Где применяются миграции (локально, через docker-compose, в пайплайне) — фактически
- Запрет на правку уже применённых миграций (новая миграция вместо изменения старой), если это наблюдается

## Выходной артефакт

- Файл: `docs/rules/migrations.md`
- Префикс правил: `MIGR`
- Формат: см. [template-rules.md](./template-rules.md)
- Каждое правило сопровождается фрагментом реального файла миграции или командой с путём к источнику

---

## Ограничения

- Источник — **только файлы миграций, команды и конфигурация проекта**; внешние эталоны не используются.
- Отсутствующие элементы (например, нет автоприменения миграций в CI) не превращаются в правила; отмечаются как «в проекте не обнаружено».
- Команда не меняет миграции и схему БД — только создаёт/обновляет документ правил.
- Доступ к данным и SQL-запросы прикладного слоя (репозитории) в этот документ не входят — это область архитектуры, см. [extract-architecture-rules.md](./extract-architecture-rules.md).
