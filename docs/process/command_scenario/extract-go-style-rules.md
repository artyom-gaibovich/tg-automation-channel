# Команда: Извлечение правил Go-стиля и написания кода

Изучает фактический стиль Go-кода проекта и формирует документ правил `docs/rules/go-style.md`. Процедурная инструкция для исполнителя (LLM-агент или разработчик), без привязки к конкретному агенту.

## Назначение

Вывести правила оформления Go-кода из реальных файлов: иммутабельность структур, конструкторы, именование, обработка ошибок, передача контекста, работа с константами, запреты (глобальное состояние, сеттеры, пакеты-утилиты, комментарии). Документ описывает то, как код **уже написан**, и закрепляет это как норму.

---

## Входные параметры

- Без обязательных аргументов — анализируется весь Go-код репозитория.
- Необязательный аргумент `scope` — путь к подкаталогу для ограничения анализа.

---

## Источники в коде

| Что смотреть | Зачем |
|--------------|-------|
| `*.go` в `internal/`, `pkg/`, `cmd/`, `configs/`, `tools/` | Основной стиль кода |
| Объявления `struct` и их поля | Экспортируемость, иммутабельность, наличие геттеров |
| Функции `New...` | Конструкторы как способ создания объектов |
| Сигнатуры методов | Позиция `context.Context` и `error` |
| Блоки `const (...)` и литералы | Константы против магических значений |
| Имена интерфейсов, структур, функций, переменных | Конвенции именования |
| `configs/` | Способ чтения конфигурации и переменных окружения |
| Наличие/отсутствие комментариев, `//nolint:` | Политика комментариев |
| `go.mod` | Версия Go и зависимости |

## Алгоритм

1. Определить корень анализа (весь репозиторий или `scope`).
2. Собрать представительную выборку файлов из разных слоёв и модулей.
3. По выборке зафиксировать повторяющиеся приёмы: как создаются объекты, как заполняются поля, есть ли мутации после конструирования.
4. Извлечь конвенции именования отдельно для интерфейсов, структур (приватных и экспортируемых), функций, констант, переменных.
5. Определить политику обработки ошибок и передачи контекста по сигнатурам.
6. Определить политику констант: что вынесено в `const`, где объявляется, как именуется.
7. Определить способ работы с конфигурацией и переменными окружения.
8. Зафиксировать явные запреты, наблюдаемые в коде (нет глобальных переменных, нет сеттеров, нет пакетов-утилит, нет/есть комментарии).
9. Сформулировать правила с префиксом `GO`; противоречивые практики отметить как частично соблюдаемые.
10. Записать `docs/rules/go-style.md` по формату из [template-rules.md](./template-rules.md) и проверить по чек-листу.

---

## Что выявлять

- Иммутабельность и заполнение полей только при конструировании
- Конструкторы `NewType(...)` против прямой инициализации
- Экспортируемость полей доменных структур и отношение к геттерам
- Именование: интерфейсы, структуры, функции, константы, переменные
- Обработка ошибок: позиция `error`, ранние возвраты, оборачивание `%w`
- Передача `context.Context` первым параметром
- Константы против магических строк и чисел; место объявления и группировка
- Конфигурация: пакет `configs`, чтение `.env` и переменных окружения
- Запреты: глобальное состояние, сеттеры, пакеты-утилиты, комментарии в коде

## Выходной артефакт

- Файл: `docs/rules/go-style.md`
- Префикс правил: `GO`
- Формат: см. [template-rules.md](./template-rules.md)
- Каждое правило сопровождается фрагментом реального кода с путём к файлу

---

## Ограничения

- Источник — **только код проекта**; внешние гайдлайны и другие документы проекта не используются как источник правил.
- Стиль выводится из наблюдаемого кода; если приём встречается непоследовательно — это отмечается явно.
- Команда не меняет исходный код — только создаёт/обновляет документ правил.
