## Назначение

Все команды извлечения правил пишут результат в единый формат. Формат повторяет стиль эталонных документов проекта (таблица правил с ID-префиксом, навигация, примеры, история версий) и совместим с CommonMark / GitHub-style Markdown.

Документ описывает **фактические** правила, выведенные из кода проекта, а не желаемые. Каждое правило подтверждается реальным примером из кодовой базы.

---

## Расположение и имя файла

- Каталог вывода: `docs/rules/`
- Имя файла: `{rule}.md` в kebab-case, отражает область (например: `architecture.md`, `go-style.md`, `linting-tests.md`, `docker-infra.md`, `cicd.md`, `api-contracts.md`)
- Один документ — одна область правил
- Каталог `docs/rules/` создаётся автоматически, если его нет

---

## Обязательная структура

Документ состоит из следующих блоков в строгом порядке:

1. Заголовок `#` — название области правил
2. Назначение — 1–3 строки, что описывает документ
3. Горизонтальный разделитель `---`
4. Раздел `## Навигация` — список якорных ссылок на разделы
5. Раздел `## Таблица правил` — таблица `| ID | Правило |` со всеми правилами
6. Тематические разделы `##` — подробное описание правил со ссылками на ID
7. Раздел `## Пример` — реальные фрагменты кода из проекта
8. Раздел `## Версионирование` — таблица истории изменений

## Идентификаторы правил

Каждое правило получает стабильный идентификатор вида `PREFIX-NNN`:

- `PREFIX` — короткий код области в верхнем регистре (3–5 букв)
- `NNN` — порядковый номер с ведущими нулями, начиная с `001`

Префикс выбирается под область и не пересекается с другими документами. Рекомендуемые префиксы:

| Область | Префикс |
|---------|---------|
| Архитектура | `ARCH` |
| Go-стиль и код | `GO` |
| Линтинг и тесты | `QA` |
| Docker / Makefile / инфраструктура | `INFRA` |
| CI/CD | `CICD` |
| API-контракты (OpenAPI, protobuf) | `API` |

В тексте разделов на правило ссылаются жирным маркером в квадратных скобках: `**[ARCH-001]**`.

## Требования к содержанию

- Язык документа — русский; идентификаторы кода и технические значения — на английском
- Запрещён встроенный HTML, Wikilinks `[[...]]`, подчёркивание заголовков `===`/`---`
- Иерархия заголовков без пропусков: `#` → `##` → `###`
- Код — только в fenced-блоках с указанием языка
- Ссылки — относительные
- Каждое правило выведено из наблюдаемого кода; если практика встречается в коде непоследовательно — это фиксируется явно как «наблюдается частично» с указанием расхождений, а не выдаётся за устоявшееся правило
- Запрещено выдумывать правила, не подтверждённые кодом; отсутствующая область отмечается как «в проекте не обнаружено»
