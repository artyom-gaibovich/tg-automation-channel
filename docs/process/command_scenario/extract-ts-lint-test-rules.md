# Команда: Извлечение правил линтинга и тестирования (TypeScript)

Изучает конфигурацию линтеров и фактический стиль тестов TypeScript-проекта и формирует документ правил `docs/rules/ts-linting-tests.md`. Процедурная инструкция для исполнителя (LLM-агент или разработчик), переиспользуемая между TypeScript-проектами.

## Назначение

Зафиксировать фактические нормы контроля качества: какие правила ESLint включены и с какими настройками, какие проверки отключены и почему, какой уровень строгости у компилятора TypeScript, как организованы тесты (структура, именование, моки, e2e). Документ выводит правила из конфигурационных файлов и из самих тестов.

> Правила форматирования (Prettier) выносятся в отдельную команду [extract-prettier-rules.md](./extract-prettier-rules.md); здесь фиксируется только связка ESLint↔Prettier (например, `plugin:prettier/recommended`).

---

## Входные параметры

- Без обязательных аргументов — анализируется весь репозиторий.
- Необязательный аргумент `scope` — путь к подкаталогу для ограничения анализа.

## Источники в коде

| Что смотреть | Зачем |
|--------------|-------|
| `.eslintrc.js` / `.eslintrc.json` / `eslint.config.mjs` | Плагины, `extends`, включённые/отключённые правила, `parserOptions` |
| `@typescript-eslint/*` правила в конфиге | Type-aware линтинг, отключённые и усиленные правила |
| `tsconfig.json` (`strict`, `strictNullChecks`, `noImplicitAny`, `noUnusedLocals`) | Строгость компилятора как часть контроля качества |
| npm-скрипты в `package.json` (`lint`, `test`, `test:e2e`, `test:cov`) | Как запускаются проверки |
| Секция `jest` в `package.json` или `jest.config.*`, `test/jest-e2e.json` | Конфигурация тест-раннера, `testRegex`, coverage |
| `*.spec.ts` / `*.test.ts` по всему дереву | Структура и стиль unit-тестов |
| `test/` каталог, `*.e2e-spec.ts`, `supertest` | Организация e2e/интеграционных тестов |
| Использование `@nestjs/testing`, `jest.mock`, `jest.fn`, тестовых модулей | Подход к мокам и изоляции |
| Директивы подавления (`// eslint-disable`, `// @ts-ignore`, `// @ts-expect-error`) | Политика исключений |

## Алгоритм

1. Определить корень анализа (весь репозиторий или `scope`).
2. Разобрать конфигурацию ESLint: `parser`, `parserOptions.project` (type-aware), список `extends` и плагинов, включённые правила и их уровень (`error`/`warn`), отключённые правила с обоснованиями (если есть в комментариях), интеграцию с Prettier.
3. Прочитать `tsconfig.json` и зафиксировать флаги строгости, влияющие на качество кода.
4. Зафиксировать команды запуска проверок из npm-скриптов (`lint`, `test`, `test:e2e`, `test:cov`).
5. Разобрать конфигурацию тест-раннера (Jest): `testRegex`/`testMatch`, `rootDir`, `collectCoverageFrom`, отдельный конфиг для e2e.
6. Собрать выборку тестов (если присутствуют) и вывести конвенции: расположение (рядом с кодом или в `test/`), имена файлов и `describe/it`, способ создания моков, использование `Test.createTestingModule`, организация e2e через `supertest`.
7. Определить политику директив подавления (`eslint-disable`, `@ts-expect-error`).
8. Сформулировать правила с префиксом `QA`; отключённые проверки описать с причиной, если она зафиксирована.
9. Записать `docs/rules/ts-linting-tests.md` по формату из [template-rules.md](./template-rules.md) и проверить по чек-листу.

---

## Что выявлять

- Линтер и его конфиг: `parser`, type-aware режим (`parserOptions.project`), `extends`, плагины
- Включённые правила уровня `error` (например, `no-floating-promises`, `no-misused-promises`, `eqeqeq`)
- Ослабленные/отключённые правила (`no-explicit-any: warn`, `explicit-function-return-type: off`) и обоснования
- Интеграция ESLint↔Prettier (`plugin:prettier/recommended`, `eslint-config-prettier`)
- Флаги строгости компилятора из `tsconfig.json`
- Команды запуска проверок из npm-скриптов
- Конфигурация тест-раннера: `testRegex`, `rootDir`, coverage, отдельный e2e-конфиг
- Структура и именование тестов (`*.spec.ts`, `describe/it`)
- Подход к мокам и изоляции (`@nestjs/testing`, `jest.mock`)
- Организация e2e/интеграционных тестов (`supertest`)
- Политика директив подавления (`eslint-disable`, `@ts-expect-error`)

## Ограничения

- Источник — **только код и конфигурация проекта**; внешние стайл-гайды не используются.
- Если тесты в проекте отсутствуют — это фиксируется как «в проекте не обнаружено», без выдумывания правил; описываются только реально настроенные линтеры и присутствующие тесты.
- Правила форматирования не описываются — они относятся к команде Prettier.
- Команда не меняет исходный код и конфигурацию — только создаёт/обновляет документ правил.

- [ ] Разобрана конфигурация ESLint (плагины, включённые, отключённые, type-aware)
- [ ] Зафиксированы флаги строгости `tsconfig.json`
- [ ] Извлечены команды запуска проверок из npm-скриптов
- [ ] Разобрана конфигурация тест-раннера (Jest) и e2e
- [ ] Выведены конвенции структуры и стиля тестов, моков (если тесты есть)
- [ ] Каждое правило подтверждено фрагментом конфига или теста с путём к файлу
- [ ] Отсутствие тестов, если оно есть, отмечено как «в проекте не обнаружено»
- [ ] Документ соответствует формату и содержит таблицу `QA-NNN`
