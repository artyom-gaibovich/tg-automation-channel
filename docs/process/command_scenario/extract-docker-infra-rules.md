# Команда: Извлечение правил Docker, Makefile и инфраструктуры

Изучает локальную инфраструктуру проекта (Dockerfile, docker-compose, Makefile, конфигурация окружения, логирование) и формирует документ правил `docs/rules/docker-infra.md`. Процедурная инструкция для исполнителя (LLM-агент или разработчик), без привязки к конкретному агенту.

## Назначение

Зафиксировать фактические стандарты сборки и локального запуска: структура Dockerfile, состав сервисов docker-compose, цели Makefile, способ конфигурирования через переменные окружения, подход к логированию. Документ выводит нормы из реальных инфраструктурных файлов.

---

## Входные параметры

- Без обязательных аргументов — анализируется весь репозиторий.
- Необязательный аргумент `scope` — путь к подкаталогу (например, конкретный микросервис).

---

## Источники в коде

| Что смотреть | Зачем |
|--------------|-------|
| `Dockerfile` | Этапы сборки, базовые образы, точка входа |
| `docker-compose.yml` | Состав сервисов, healthcheck, зависимости, профили, порты |
| `.env`, `.env.example` | Набор переменных окружения и дефолты |
| `Makefile` | Переменные, цели сборки/запуска/миграций/CI, `.PHONY` |
| `.githooks/`, `scripts/` | Хуки и вспомогательные скрипты |
| Пакет логирования (`tools/logging`, использование `level.*`) | Логгер, уровни, формат, контекстное логирование |
| `migrations/` | Способ применения миграций (Liquibase/иное) |

---

## Алгоритм

1. Определить корень анализа (весь репозиторий или `scope`).
2. Разобрать Dockerfile: этапность, базовые образы, флаги сборки, что попадает в финальный образ, точка входа.
3. Разобрать docker-compose: перечень сервисов, их образы, healthcheck, `depends_on`, профили, способ задания портов, источник конфигурации.
4. Сопоставить переменные из `.env.example` с их использованием в compose и коде.
5. Разобрать Makefile: блок переменных, цели и их команды, агрегирующие цели, `.PHONY`.
6. Зафиксировать политику логирования: библиотека логгера, уровни, формат, структура полей сообщения, передача логгера через контекст.
7. Описать способ применения миграций.
8. Сформулировать правила с префиксом `INFRA`; непоследовательные практики отметить явно.
9. Записать `docs/rules/docker-infra.md` по формату из [template-rules.md](./template-rules.md) и проверить по чек-листу.

---

## Что выявлять

- Многоэтапность Dockerfile, базовые образы, флаги сборки, точка входа
- Состав сервисов compose и их назначение
- Healthcheck и порядок запуска через зависимости
- Профили запуска (например, миграции)
- Конфигурирование через переменные окружения, разделение внутренних и хостовых портов
- Запрет хардкода секретов и хостов в compose
- Структура Makefile: переменные, цели, `.PHONY`, агрегирующая цель CI
- Цели инициализации окружения, хуков, инструментов
- Логирование: библиотека, уровни, JSON-формат, структура полей, контекст
- Способ и место применения миграций

## Выходной артефакт

- Файл: `docs/rules/docker-infra.md`
- Префикс правил: `INFRA`
- Формат: см. [template-rules.md](./template-rules.md)
- Фрагменты конфигов приводятся из реальных файлов с указанием пути

---

## Ограничения

- Источник — **только инфраструктурные файлы проекта**; внешние эталоны не используются.
- Отсутствующие элементы (например, нет Kafka или нет профиля миграций) не превращаются в правила; при необходимости отмечаются как «в проекте не обнаружено».
- Команда не меняет инфраструктурные файлы — только создаёт/обновляет документ правил.
- CI/CD и оркестрация (Helm, Kubernetes, пайплайны) в этот документ не входят — для них отдельная команда [extract-cicd-rules.md](./extract-cicd-rules.md).
